# Kazemi Grouped 4-Fold + Decoder-Score Experiment

This note documents the participant splits, random seeds, decoder search, checkpoints, and per-window predictions for the **Kazemi grouped 4-fold + validation decoder-score** experiment.

> **Cross-cluster note:** All `/anvil/...` paths below are local to the Anvil cluster and will not be accessible from another cluster. They identify the original files only. To reproduce or inspect the experiment elsewhere, the source snapshot, split/summary files, prediction CSVs, and (if inference is required) checkpoint files must be transferred explicitly.

## 1. Experiment overview

| Item | Setting |
|---|---|
| Task | PPG peak detection → corrected IBI → 5-minute SDNN/RMSSD |
| Input | Earring, green PPG channel |
| Backbone | Kazemi-inspired PeakNet |
| Cross-validation | Fixed participant-grouped 4-fold |
| Participants | 16 |
| Training epochs | Maximum 20, early stopping patience 5 |
| Learning rate | 0.0001 |
| Batch size | 8 |
| Resampling rate | 50 Hz |
| IBI correction | Local-median correction |
| Job array | `20824089_0`–`20824089_3` |
| Held-out windows | 11,788 total |

All four folds passed the participant leakage check.

## 2. Fixed participant splits

The participant assignments are fixed in `GROUP4_TEST_FOLDS` and `GROUP4_VALIDATION`. They are not regenerated randomly for each run. Training participants are all participants not assigned to that fold's validation or test set.

|---|---|---|---|
| 0 | P1, P10, P13, P15, P18, P19, P4, P6, P8, P9 | P7, P12 | P3, P5, P11, P20 |
| 1 | P11, P12, P19, P20, P3, P4, P5, P6, P8, P9 | P10, P15 | P18, P1, P13, P7 |
| 2 | P1, P10, P11, P12, P13, P18, P20, P3, P5, P7 | P4, P8 | P9, P6, P15, P19 |
| 3 | P1, P11, P15, P18, P20, P3, P5, P6, P7, P9 | P13, P19 | P4, P12, P8, P10 |

The four test sets are mutually exclusive and together cover all 16 participants exactly once.

## 3. Random seeds

The seed bookkeeping has two levels:

```text
Experiment seed index written in filenames/config: 0
Initial global seed before grouped-fold dispatch: 40
Actual grouped-fold training RNG seed: 1
```

The grouped runner was called with `seed_idx=0` and then executed:

```python
set_seed(seed_idx * 10 + 1)
```

Therefore, the actual training RNG seed was `1`. The `_seed0` suffix in checkpoint filenames refers to the experiment seed index, not directly to `torch.manual_seed(0)`.

The seed function sets `PYTHONHASHSEED`, Python `random`, NumPy, PyTorch CPU, and PyTorch CUDA seeds.

## 4. Validation decoder-score selection

Checkpoint and probability-threshold selection used **validation participants only**. Test participants were not used for model or decoder selection.

The score was:

\[
S = F1_{\mathrm{event}}
-0.5\left|\frac{N_{\mathrm{pred}}}{N_{\mathrm{true}}}-1\right|
-0.25(\text{RR correction ratio}).
\]

| Decoder item | Value |
|---|---:|
| Count-ratio penalty | 0.5 |
| RR-correction penalty | 0.25 |
| Hard-negative weight | 0.0 |
| Minimum peak distance | 300 ms |
| Peak prominence | 0.0 |
| IBI deviation threshold | 0.20 |

The probability-threshold candidates were generated by:

```python
np.arange(0.10, 0.81, 0.05)
```

Exact candidate set:

```text
0.10, 0.15, 0.20, 0.25, 0.30,
0.35, 0.40, 0.45, 0.50, 0.55,
0.60, 0.65, 0.70, 0.75, 0.80
```

Only the probability threshold was swept. Prominence and minimum peak distance were fixed.

### Selected validation settings

| Fold | Threshold | Validation event F1 | Decoder score | Count ratio | RR correction ratio |
|---|---:|---:|---:|---:|---:|
| 0 | 0.60 | 0.306 | 0.276 | 1.009 | 0.101 |
| 1 | 0.60 | 0.267 | 0.263 | 0.999 | 0.018 |
| 2 | 0.60 | 0.469 | 0.456 | 1.006 | 0.039 |
| 3 | 0.60 | 0.338 | 0.336 | 0.999 | 0.005 |

All four folds independently selected threshold `0.60`.

## 5. Reconstructed execution command

The original transient Slurm submission script was not retained. The following command is reconstructed from the exact run-source snapshots, output logs, checkpoint filenames, and saved configurations. It should be labeled **reconstructed command**, not the original preserved Slurm file.

```bash
export PEAK_TARGET_MODE=kazemi
export PEAK_MIN_DISTANCE_MS=300
export PEAK_PROMINENCE=0.0
export PEAK_HARD_NEG_WEIGHT=0.0
export PEAK_COUNT_PENALTY=0.5
export PEAK_CORRECTION_PENALTY=0.25
unset PEAK_FIXED_THRESHOLD

python -u main_supervised_group4_kazemi_decoder_score.py \
  --task peak \
  --device_name earring \
  --peak_channels green \
  --peak_backbone kazemi \
  --ibi_method median \
  --group_fold "$SLURM_ARRAY_TASK_ID" \
  --group_output_dir /path/to/kazemi_group4_decoder_full \
  --batch_size 8 \
  --n_epoch 20 \
  --patience 5 \
  --lr 0.0001 \
  --data_dir /path/to/synced_3device_rawaligned_training_v1_stride30_rawslots \
  --cuda 0 \
  --resample_hz 50.0
```

Paths must be replaced for the destination cluster. The destination dataset must contain the same participant NPZ files and fields.

## 11. Reproducibility limitations

1. The original Slurm submission script was transient and was not retained; the command above is reconstructed from saved evidence.
2. Anvil absolute paths are cluster-local and must be replaced on another system.
3. Checkpoint filenames contain `seed0`, while the grouped runner's actual training RNG seed was `1`.
4. The four prediction files are the authoritative held-out window outputs for the reported metrics.
5. Any retraining comparison should preserve the fixed participant splits and should not tune decoder settings on held-out test participants.
